Data limits and measurement

Group membership comes from the existing .9 inventory file. The live database has neither a project field nor a release-target field. New release items need to be added to that inventory; this view does not infer membership from titles. Current titles, recorded states, assignments, review returns, and turn gaps are read from the live database while this page is visible, every 15 seconds. Failed reads preserve the last view and show it as stale. Closing a record does not establish that its code shipped.

Each sector is an archetype found in this item's assignments or turns. Turn session archetypes take precedence; assignments use their holder archetype. Missing archetypes appear as Unknown. Current archetype metadata is not historical proof for every turn, and narrative titles do not supply attribution. Tests or landing performed within an archetype remain part of that archetype; the database cannot separate them reliably.

Colors count linked reviews requesting changes against the producer archetype. A later review linked to the same producer adds a return to the later reviewer archetype. These are recorded returns, not every workflow revisit and not necessarily waste. No return record means no recorded return, not proof of a first visit.

Histogram samples run from a turn's end to the next turn's start in the same recorded archetype, including across assignments and agents. Only directly assignment-linked turns count. Overlaps and unknown ends are excluded. Gaps may include legitimate work in another stage; they do not prove idle time or a stall. Current stage and percentage complete are not recorded and are not guessed.

All circles share the radius scale and bins. Alpha is bin count divided by the highest visible bin count in that slice. Each bin is hard-edged. Longer gaps are counted separately in the striped overflow rim. Log radius uses log(1 + seconds). An item with no recorded assignments or turns is shown as an empty outline.
